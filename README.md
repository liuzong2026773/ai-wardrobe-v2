# AI 电子衣橱 v2（干净新工程）

给老婆做的离线 AI 电子衣橱：导入衣服、按天气/心情自动推荐、静态试穿、实时 AR 试衣镜。
Android 先行，零付费云端 API，全本地运行。

## 功能清单

- [x] **衣橱**：拍照录入现有衣服 / 从相册导入购物网站保存的图片；ML Kit 抠图去底（失败用原图）；分类 / 颜色 / 季节 / 心情 / 温度范围标签；收藏、编辑、删除
- [x] **穿搭**：免费 Open-Meteo 天气（免 Key，无定位/无网默认 20°C）；心情选择（休闲/正式/运动/约会/通勤）；本地打分规则推荐 3 套；一键去 AR 试衣 / 静态试穿；保存到穿搭日历（按日期查看）
- [x] **静态试穿**：拍/选一张全身照，上衣+下装叠加显示，可拖动、双指缩放，保存到今天
- [x] **AR试衣**：前置摄像头 + ML Kit 姿态关键点，上衣按肩宽/躯干长、下装按胯宽/腿长分层贴合；可切换摄像头、镜像开关；离开页面即释放相机

## 防闪退设计（针对旧版一点就闪退的问题）

旧版在 Android 16 一加手机上一点就闪退、应用数据 0B，即启动时就崩了。v2 针对这点做了：

1. **启动路径最简**：`main()` 只做 `runApp`，不初始化数据库、不碰相机、不加载任何原生 AI 库。
2. **懒加载**：SQLite 第一次打开衣橱时才建库；相机/姿态检测器只在 AR 页打开时创建，离开即释放；抠图只在导入衣服时调用。
3. **不用重型原生库**：没有 drift/build_runner、opencv_dart、flutter_onnxruntime；抠图只用 ML Kit subject segmentation，失败就用原图。
4. **不用 IndexedStack**：4 个 tab 按需创建，不会一启动就把 AR 页的相机也初始化了。
5. **Android 配置固定**：minSdk 24、targetSdk 36、compileSdk 36、NDK 27.2.12479018（支持 Android 16 的 16KB 内存页）；完整的 android/ 脚手架提交进仓库，CI 绝不跑 `flutter create`。
6. **失败只影响单个页面**：相机/检测器/天气任何一步失败，都只显示错误提示，不会让整个 App 退掉。

## 试衣效果说明（按用户硬要求）

- **真实衣服**：试衣用的永远是用户自己导入/拍照的那件真实衣服的抠图。代码里没有任何内置样衣，也不生成假衣服；衣橱空着，试衣镜里就什么都不画。
- **对位**：每帧用 ML Kit 姿态关键点（肩/髋/膝/肘/腕）重新算衣服位置，单应性透视变换贴合——旋转、缩放、透视一次完成，衣服跟着身体走；抠图边缘做过羽化，手臂挡在衣服前面时会擦除衣服、露出真实手臂。
- **绝不付费**：试衣全程本机完成（ML Kit 姿态+抠图、本机图像变换），没有任何付费接口、付费云端 API、按量扣费服务；天气只用免费免 Key 的 Open-Meteo。
- **实时本机渲染**：姿态检测、衣服变形贴合都在手机本机跑，不走云端。

## 已知局限（实话）

- 袖子不跟手臂走：整件上衣按躯干四边形贴合，长袖不会顺着手臂弯曲。
- 没有布料褶皱/垂坠/遮挡级真实感：那种效果要生成式扩散模型才有，本机不做、云端不调（用户明确不要付费方案）。
- 遮挡只处理了手臂；手里拿东西挡在身前、两个人入镜时效果会打折。
- 姿态检测约 8 帧/秒，动作很快时衣服跟随会有半拍延迟。
- 抠图依赖 ML Kit 模型首次下载（Google Play 服务），没网的手机第一次抠图可能失败，会自动用原图。
- 天气需要定位权限 + 联网；拒绝定位或没网时按 20°C 推荐。

## 手机测试步骤

1. 先卸载手机上旧的 AI 电子衣橱（包名不同可不卸，但建议卸干净）。
2. 安装 `app-arm64-v8a-release.apk`。
3. 打开 App：应直接进“我的衣橱”（空衣橱提示），不闪退。
4. 点“添加衣服”拍一件上衣，看抠图白底对不对；再加一件下装。
5. 去“穿搭”页：点“刷新天气”，选心情，点“为我推荐 3 套”，应出 3 套。
6. 点一套的“AR试衣”：前置摄像头打开，站远全身入镜，看衣服是否贴在肩/胯位置；再点“静态试穿”：拍全身照，拖动衣服调位置。
7. 哪一步报错，把截图/报错原话发回来修。
